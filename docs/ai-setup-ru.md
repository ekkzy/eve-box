# Установка softlumi с помощью ИИ

Комплект позволяет ИИ с доступом к локальному терминалу Windows проверить APK, подготовить план установки и применить его после твоего подтверждения. Обычный чат без доступа к компьютеру может объяснить шаги, но не выполнить их. Поддерживаются Windows PowerShell 5.1 и PowerShell 7.

Комплект доступен в [закрытом предварительном релизе](https://github.com/ekkzy/softlumi/releases/tag/v0.3.0-candidate.14-setup.1). Для загрузки нужен доступ к приватному репозиторию. Профиль Mi Box S 3 основан на конфигурации, которой владелец проекта пользуется на своей приставке.

## Что проверено

Новый установщик прошёл 66 офлайн-сценариев в PowerShell 5.1/7 и полный цикл установки, смены HOME и возврата на собственном API 34 эмуляторе с реальным UI 3840×2160. На физической Mi Box S 3 выполнен только `Plan`, без изменений. Полный проход нового установщика на приставке с заводской конфигурацией ещё не проверялся. [Подробности проверок](ai-setup-validation.md).

## Как начать

1. Скачай [softlumi-ai-setup-candidate.14.zip](https://github.com/ekkzy/softlumi/releases/download/v0.3.0-candidate.14-setup.1/softlumi-ai-setup-candidate.14.zip) со страницы релиза и распакуй в отдельную папку. Не передавай ИИ пароль GitHub или токен доступа.
2. Открой эту папку в ИИ-помощнике с локальным терминалом. Передай ему [промпт установки](installation-prompt-ru.md). Сначала он должен показать конкретный план для выбранного устройства.
3. Подтверди только понятный тебе план. По умолчанию комплект устанавливает softlumi и открывает приложение; HOME, другие приложения и системные настройки остаются прежними.

Для работы нужны доверенные Android SDK Platform-Tools (`adb`), Build-Tools (`apksigner`, `aapt`) и Java для `apksigner`. Пути в примере ниже нужно заменить на установленные у тебя. Если инструментов нет, помощник должен объяснить установку официальных Android SDK tools до продолжения. Официальные страницы: [Platform-Tools](https://developer.android.com/tools/releases/platform-tools), [подключение ADB](https://developer.android.com/tools/adb), [проверка подписи APK](https://developer.android.com/tools/apksigner).

Включение режима разработчика, отладку, подтверждение RSA на ТВ и wireless pairing при наличии такой функции выполняешь ты. Установщик сам не делает `connect`, `pair` или `tcpip`. При нескольких подключённых устройствах нужно явно выбрать нужное. Старый IP, `ANDROID_SERIAL` и единственная строка в списке устройств не заменяют этот выбор.

## Что можно выбрать

Профиль `generic-install-only` подходит для установки и пробного запуска без изменения HOME и отключения пакетов. Он выбран по умолчанию.

Профиль `mi-box-s3-android14` допускает дополнительные действия только при точном совпадении модели, API и fingerprint из `scripts/setup-profiles/mi-box-s3-android14.json`: модель `MiTV-AFMU0`, API 34, конкретная сборка Xiaomi Android 14. Названия «Mi Box S 3» недостаточно. На другой прошивке этот профиль откажет в работе; остаётся базовая установка. Редактировать профиль ради обхода проверки не следует.

Все дополнительные действия выключены по умолчанию:

| Выбор | Что изменится |
| --- | --- |
| Назначить softlumi основным HOME | Запрошен переход на softlumi. Фактическую кнопку Home нужно проверить отдельно. |
| Отключить Google TV Home | Штатный лаунчер станет недоступен пользователю Android 0. Допускается только вместе с переходом HOME; прежнее состояние записывается в журнал. |
| Netflix, Prime Video, YouTube Music, Mi Music | Выбранное приложение станет недоступно пользователю Android 0. Выбирай только то, чем не пользуешься. |
| Google Play Games | Станет недоступен его интерфейс игр и профиля. Это не обещание отключить все игровые службы. |
| Xiaomi analytics | Будет отключён один указанный пакет Xiaomi. Другие приложения по-прежнему могут передавать телеметрию. |
| Google Feedback | Могут стать недоступны отправка отзывов и диагностические отчёты через этот пакет. Остальные механизмы отчётов остаются отдельными. |

Это ограниченный список выбора, а не копия всех отключённых приложений с другой приставки. Комплект не обещает убрать всю рекламу, снизить расход памяти или увеличить частоту кадров. Если выбранного пакета нет, план не будет применён частично. Уже отключённый пакет записывается как действие без изменения состояния.

Службы старого лаунчера и переназначения кнопок требуют отдельного внимания. Например, оставшаяся служба Free My TV может перенаправлять открытие Google TV Home, а другая служба — обрабатывать брендовые кнопки. Комплект их не отключает и не настраивает. При конфликте нужно остановиться и разобрать его, сохранив прежнее состояние. Setup Wizard, хранилище, медиа-службы и OEM-компоненты HOME в список отключений не входят. Заставка, сон, CEC и голосовое управление не настраиваются.

## Проверка комплекта и план

Команды выполняются из корня распакованного ZIP. В нём метаданные находятся в `manifest.json`; в репозитории — в [`distribution/ai-setup/manifest.json`](https://github.com/ekkzy/softlumi/blob/main/distribution/ai-setup/manifest.json). Сначала сверь комплект с доверенной страницей издателя и метаданными репозитория. Хеш, самостоятельно вычисленный у неизвестного файла, не подтверждает его происхождение.

В manifest указаны SHA-256 файлов комплекта, APK и сертификата, package и версия. Установщик проверяет APK через `apksigner` и `aapt`. Ожидаемый пакет — `io.github.ekkzy.softlumi`. Несовпадение подписи, версии или уже установленного приложения нужно разобрать; удаление старого APK и очистка данных не являются автоматическим решением.

```powershell
$setupTarget = @{
    Serial = '<явно выбранный serial>'
    ExpectedModel = '<модель выбранного ТВ>'
    ExpectedFingerprint = '<build fingerprint выбранного ТВ>'
    AdbPath = 'C:\Android\Sdk\platform-tools\adb.exe'
}
$setupManifest = Get-Content .\manifest.json -Raw -Encoding UTF8 | ConvertFrom-Json
New-Item -ItemType Directory -Path .\setup-private -Force | Out-Null
$setupPlan = '.\setup-private\plan-01.json'

.\scripts\setup-tv.ps1 -Mode Plan @setupTarget `
    -Apk $setupManifest.apk.file -ApkSha256 $setupManifest.apk.sha256 `
    -SigningCertSha256 $setupManifest.apk.signingCertSha256 `
    -ApkSignerPath 'C:\Android\Sdk\build-tools\35.0.0\apksigner.bat' `
    -AaptPath 'C:\Android\Sdk\build-tools\35.0.0\aapt.exe' -PlanPath $setupPlan

$setupApprovedSha = (Get-FileHash $setupPlan -Algorithm SHA256).Hash.ToLowerInvariant()
```

`Plan` читает состояние выбранного ТВ через ADB и сохраняет локальный файл; изменения на ТВ не применяет. Помощник должен показать устройство, APK, прежний и запрошенный HOME, все выбранные пакеты, действия без изменений и условия возврата. Перед `Apply` подтвердите именно показанный файл и его SHA-256. Нельзя изменить план и автоматически пересчитать «одобренный» хеш. План действует 30 минут; новый или просроченный план требует нового просмотра.

Для перехода HOME в команду **Plan** добавляются `-ProfileId mi-box-s3-android14 -SetHome`. Отключение штатного Home дополнительно требует `-DisableStockHome`. Необязательные приложения задаются через `-DisablePackages` как массив точных package names из профиля. Эти ключи не нужно добавлять для базовой установки.

После подтверждения плана:

```powershell
.\scripts\setup-tv.ps1 -Mode Apply @setupTarget -PlanPath $setupPlan `
    -ApprovedPlanSha256 $setupApprovedSha -JournalPath .\setup-private\apply-01.json

.\scripts\setup-tv.ps1 -Mode Inspect @setupTarget `
    -JournalPath .\setup-private\apply-01.json
```

Для каждой новой операции используй новые имена плана и журнала. `Apply` сначала устанавливает и проверяет APK, затем открывает softlumi и подтверждает его передний план. Только после этого выполняются выбранные изменения пакетов и HOME. `Inspect` читает фактическое состояние, не исправляет его и не переписывает журнал.

## Что проверить после установки

Проверь кнопку Home на физическом пульте, Back, запуск приложений, избранное и его порядок. Если пользуешься голосовым поиском, Cast или переназначенными кнопками, проверь их отдельно. Ответ Android `Success` и HOME role-holder сами по себе не доказывают поведение пульта.

«Продолжить просмотр» зависит от реального доступа Android и источников. Установка не выдаёт доступ к чужой истории автоматически; демонстрационные карточки не заменяют личные данные. Системная заставка и таймеры сна сохраняются, но их длительное срабатывание не считается проверенным без наблюдения.

## Возврат и ошибки

Сначала прочитай результат `Inspect` и журнал, затем при необходимости выполни:

```powershell
.\scripts\setup-tv.ps1 -Mode Restore @setupTarget `
    -JournalPath .\setup-private\apply-01.json
```

`Restore` использует записанное прежнее состояние HOME и пакетов, включая частично выполненный план. Установленный APK softlumi и его данные сохраняются. Прежняя версия APK автоматически не возвращается. Массового включения штатных приложений нет. Автоматический возврат ограничен журналами не старше 14 дней; изменение прошивки или ADB-инструмента также требует отдельного разбора. Если состояние после установки уже изменил другой инструмент или пользователь, конфликт требует разбора; исправлять журнал вручную нельзя.

Если ответ ADB потерян после отключения штатного HOME, `Inspect` может показать `homeRestoreDeferredUntilOldPackage: true`. Тогда `Restore` сначала возвращает прежнее состояние только затронутого пакета HOME. Если Android по-прежнему выбирает неизвестный сторонний HOME, возврат останавливается с ошибкой, не меняя этот выбор. Это частичный результат: штатный пакет уже может быть восстановлен, а остальные шаги — ещё нет. Сверь журнал и разбери конфликт перед продолжением.

При тайм-ауте или потере соединения результат установки APK может быть неизвестен. `Inspect` сообщает об этом как `installOutcomeUnknown: true`; журнал может иметь статус `NeedsReconcile`. Наблюдаемая версия и SHA APK не снимают эту неопределённость и не разрешают автоматический повтор. `Restore` в таком состоянии отказывает с `install_outcome_unknown_no_automatic_retry`. Изменения пакетов и HOME ещё не начинались, поэтому возвращать конфигурацию профиля не требуется. Сначала нужно отдельно проверить завершение или устранить незавершённую установочную сессию Android, затем создать новый план. Не удаляй приложение, не очищай данные и не выполняй downgrade ради обхода ошибки.

Планы и журналы содержат идентификатор устройства, сведения о сборке, HOME и пакетах. Храни `setup-private` локально. Не публикуй эти файлы, личную историю, аккаунты, адреса и диагностические логи. Итог помощника должен отделять выполненные проверки от ошибок и непроверенных сценариев.
